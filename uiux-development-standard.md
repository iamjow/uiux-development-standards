# CLAUDE.md
# UIUX Development Standards

## Objective

Generate a production-ready frontend implementation that follows the UI/UX development standards.

The generated output should require minimal manual cleanup and be ready for implementation.

---

# UI Technology Standards

Use the following technologies for UI implementation:

- HTML5
- SCSS
- JavaScript

These standards apply regardless of the frontend framework being used.

Do NOT use:

- Tailwind CSS
- Bootstrap
- Bulma
- Material UI
- Foundation
- CSS-in-JS libraries
- Inline styles

---

# HTML Standards

Use semantic HTML5.

Preferred elements include:

- header
- nav
- main
- section
- article
- aside
- footer
- form
- table

Requirements:

- Clean DOM structure
- No unnecessary wrapper divs
- Proper heading hierarchy
- Accessible markup
- Logical element grouping

---

# SCSS Standards

All styling must be written using SCSS.

Never generate:

- Inline styles
- Embedded CSS
- HTML style attributes

Use reusable SCSS architecture.

Example:

style/

    app.scss

    _variables.scss

    _mixins.scss

    _global.scss

    components/

        _button.scss

        _card.scss

        _table.scss

        _form.scss

        _modal.scss

        _navigation.scss

    layouts/

        _header.scss

        _footer.scss

        _sidebar.scss

        _content.scss

    pages/

        _dashboard.scss

        _settings.scss

        _profile.scss

    responsive/

        _mobile.scss

        _tablet.scss

        _desktop.scss

---

# Component Standards

Create reusable components whenever possible.

Examples:

- Buttons
- Cards
- Forms
- Inputs
- Dropdowns
- Tables
- Tabs
- Badges
- Alerts
- Navigation
- Sidebar
- Header
- Footer
- Modal
- Pagination

Avoid duplicate styling.

Shared components should share the same SCSS.

---

# Naming Convention

Use kebab-case.

Examples:

customer-card

order-table

user-profile

Avoid autogenerated class names.

Avoid random IDs.

Use meaningful names.

---

# SCSS Organization

Each component should own its styles.

Example:

components/

_button.scss

_card.scss

_table.scss

Avoid placing all styles inside one file.

---

# Layout

Keep layouts modular.

Separate:

- Header
- Sidebar
- Main Content
- Footer

Each layout should have its own SCSS file.

---

# Responsive Design

Support:

- Desktop
- Tablet
- Mobile

Use responsive SCSS.

Avoid duplicated layouts.

Prefer flexible layouts using:

- Flexbox
- CSS Grid

---

# Design Consistency

Maintain consistent:

- spacing
- typography
- border radius
- colors
- shadows
- alignment

Use reusable variables whenever possible.

---

# Accessibility

Follow semantic HTML.

Include:

- labels
- alt attributes
- button types
- keyboard-friendly elements

---

# Design Tokens / Theme Variables

All colors, fonts, and other reusable design values
must be defined as variables/tokens.

Do NOT hardcode repeated colors or font families directly inside component styles.

The project must be structured so that branding or theme changes can be made
from a centralized variables file with minimal code changes.

# Performance

Avoid:

- duplicate HTML
- duplicate CSS
- deeply nested elements
- unnecessary wrappers

Keep markup clean and maintainable.

---

# JavaScript

Keep JavaScript separate from HTML.

Do not embed large scripts inside HTML.

Keep functionality modular.

---

# Output Requirements

The generated project must:

✓ Use HTML5

✓ Use SCSS

✓ Use semantic HTML

✓ Use reusable components

✓ Separate HTML, SCSS, and JavaScript

✓ Follow the defined folder structure

✓ Use centralized design tokens for reusable colors, fonts, and other theme values

✓ Make colors and fonts easy to update for future reskin or branding changes

✓ Implement responsive behavior only when responsive requirements are provided

✓ Use Vanilla JavaScript only when is required

✓ Follow browser compatibility standards for commonly used modern browsers

✓ Be maintainable and scalable

✓ Be production-ready

---

# Important

Always generate code that follows these standards unless explicitly instructed otherwise.

Do not prioritize speed over code quality.

Consistency, maintainability, and scalability are the primary goals.
